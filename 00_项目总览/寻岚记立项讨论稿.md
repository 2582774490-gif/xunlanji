# 《寻岚记》立项讨论稿 v0.4

> 定位：原创国风 2D MMORPG，首发以微信小游戏为目标，保留未来发布 Android/iOS App 的能力。轻主线、强探索、可控随机、玩家交易和竞技是核心。本文是讨论底稿，不代表开始开发或最终定案。

## 1. 一句话愿景

玩家扮演一名从凡俗起步的修行者，在山海、古城、秘境和裂隙之间观察并追寻“岚”留下的变化；通过修炼、探索、炼制、结交同道和宗门协作，决定自己在这个不断变化的修仙世界中走出怎样的道途。

## 2. 《寻岚记》名称与世界观

### 名称提供的方向

- **寻**：不是天生无敌，而是主动探索、考据、寻人、寻物、寻道；天然适合“凡人起步”的成长线。
- **岚**：山间雾气、远山层次与东方留白感，可成为游戏最核心的原创灵性现象，而非只是一种意境词。
- **记**：一段旅途的见闻录，支持地图探索、人物小传、秘境手记、玩家收藏图鉴；它比“XX仙途”更有人文和冒险气质。

### “岚”的正式设定：专项草案 v0.1，待共同确认

此前文档里的“岚网、岚息、听岚印、岚印六阶、坠岚”均为我临时举例产生的占位词，**不是来自《凡人修仙传》或任何既有作品，也不是已确认的《寻岚记》设定；现全部撤回，不进入项目资产、剧情或代码。**

本轮已形成独立的[“岚”世界观专项草案](岚世界观专项草案.md)：岚是灵气在地域环境中流变形成的“灵性天气”。以下内容以该草案为当前讨论基底，仍未锁定起源真相、失衡原因、社会定位与最终美术表现。

当前创作原则：

1. “岚”必须具有一个可用一句话说清的核心含义，并与游戏名、地图探索、随机机缘和世界历史同时相扣。
2. “岚”不应该为了特别而取代玩家熟悉、成熟的修仙境界语言。
3. 主线只负责让玩家理解世界谜团与修炼常识；完整真相可随资料片逐步揭示。

“岚”将继续经过专门的世界观创作阶段：词义与意象 → 它在天地中的位置 → 它为何会影响机缘 → 它与修士/妖兽/宗门的关系 → 它的历史代价与终极谜团。未完成这五步前，不新增不必要的“岚X”专有名词。

### 名称是否贴切

**贴切，建议保留。** 它简洁、易记，有画面感，又能形成“寻岚者”“岚记图鉴”“归岚之战”等自然的产品语言。风险是“岚”较文艺，首次传播时需用副标题讲清品类：

`《寻岚记》—— 雾起山海，凡人问道`

暂不建议改名。若后续发现商标或同名冲突，再从“寻岚录”“问岚行”“归岚纪”中选择；其中仍以《寻岚记》最佳。

## 3. 产品边界与核心循环

目标定义为 **2D MMORPG：持久角色成长 + 多人共享区域 + 个人随机机缘 + 在线交易/PVP**。它不是把单机地图联网，而是让玩家同时处于同一世界的分线/频道，在城镇、野外、资源争夺、宗门活动、拍卖行和战场中相遇。

核心循环：

`探索区域 → 观察环境变化并发现个人机缘/洞府 → 战斗、采集或抉择 → 获得有差异的材料与残卷 → 修炼/炼制/打造构筑 → 拍卖、协作或竞技 → 进入更高风险区域`

MMO 的地图和机缘采用三层结构：

- **共享世界层**：城镇、野外和公共资源点；同区玩家可相遇、组队、交易、争夺并参与世界事件。
- **个人机缘层**：每位玩家独立触发的洞府、奇遇、传承线索和选择结果；它们由服务端为该角色生成，不会因先到先得而完全被别人抢空。
- **动态区域层**：地图按时段刷新资源、精英、秘境入口和环境词缀；玩家共同发现和竞争，但有刷新规则、区域上限与基础保障。

首期在线功能应包括好友、宗门、组队秘境、排行榜、邮件、拍卖行、1v1 论剑场。跨服大世界、实时大规模帮战和超大同屏活动作为资料片目标。拍卖行、随机刷新、物品、货币与 PVP 胜负均须服务端权威结算。

### 可控随机：每位玩家都有自己的机缘

- **个人机缘**：按角色道途、已探索区域和当前环境状态出现不同的路遇、洞府、残卷、灵兽或选择支。
- **区域变化**：地图按日/周生成环境倾向与危险词缀，影响敌人、资源、秘境入口和宗门共同目标。
- **随机但不堵路**：洞府和命器可随机产出，仍设等级下限、定向重铸、碎片兑换与失败保护；稀有感来自发现和取舍，而不是无限刷取。
- **可交易与不可交易分层**：基础养成材料绑定以保障进度；稀有素材、外观和极品词条允许拍卖。拍卖行需有挂单费、成交税、价格提示与异常交易监测。

### PVP 分层

- **首发：论剑场**。实时 1v1，按段位匹配；关键属性压缩，确保技巧和构筑有效而非单纯比充值。
- **后续：灵境争夺区**。可选的有限冲突区域，争夺短时出现的环境资源；不掉落核心养成装备。
- **后续：赛季宗门战**。待玩法、网络同步和服务端稳定后才立项，不能承诺进入首发。

## 4. 内容骨架（原创）

### 地图与区域

各区域的资源、固定副本、个人机缘和动态副本配置，见[地图生态配置草案](地图生态配置草案.md)。

| 阶段 | 区域 | 视觉/玩法关键词 |
|---|---|---|
| 起步 | 雾隐原 | 山村、古道、灵草采集、教学秘境 |
| 初境 | 青璃山庭 | 云瀑、道观、宗门试炼、御器入门 |
| 中境 | 赤烬荒台 | 火山遗迹、炼器、妖潮防守 |
| 中境 | 沧溟群屿 | 海雾、沉船洞府、水系灵兽、航路探索 |
| 后境 | 悬阙天隙 | 浮空断城、天地裂隙、团队首领 |

### 修炼体系

建议先采用中国修仙读者最熟悉的经典大境界作为正式基础：**炼气 → 筑基 → 结丹 → 元婴 → 化神 → 炼虚（后续可扩展合体、渡劫、大乘）**。这不是抄袭某一部小说，而是中国修仙题材长期使用的通用类型语言；具体小境界、破境条件、功法逻辑、天劫与高阶世界规则由《寻岚记》原创。

此前的“岚印六阶”已废弃。后续若“岚”的正式设定需要影响修行，应表现为机缘、功法分支、秘境规则或世界谜团，而不是生硬替换经典境界。

战斗构筑使用三条可并行培养但要做取舍的“道途”：

- **御器**：飞剑、法印、灵傀，远程连击与控制。
- **炼体**：护体、拳兵、震荡，近战生存与爆发。
- **灵契**：灵兽、阵图、符箓，召唤、辅助与场地控制。

### 道具、势力与社交

- 道具：地域材料、丹引、命器、阵图、残卷、灵契；全部服务于收集、构筑、制造或外观，避免无意义道具膨胀。
- 可加入的世界宗门与玩家自建仙盟是两套系统：前者提供身份、门规、晋升、退出后果和 NPC 关系；后者提供自由社交、团队协作和赛季活动。详细规则见[宗门与 NPC 系统草案](宗门与NPC系统草案.md)。
- 世界宗门工作名：栖云观（守序修行）、百工楼（炼器与商路）、沧溟舟盟（航路与情报）、烬原遗民（上古真相）。所有名称和具体关系仍可修改，但不得直接沿用既有小说设定。

### 游戏板块架构

游戏首页采用“**寻岚、修行、行囊、宗门、同道**”五个常驻入口；洞府、事务簿、集市和斗法为按场景或需求展开的二级入口。这样可确保地图始终是视觉中心，避免将副本、活动、养成、社交堆成互不相干的按钮。

- **寻岚**：区域岚象、公开资源、个人线索、固定副本、动态副本与世界事件；这是开放世界的核心入口。
- **修行**：境界、功法、术法、法宝、灵兽与突破准备；培养必须服务于探索和战斗构筑。
- **行囊与百业**：装备/材料/图鉴，以及首发的炼丹、炼器、制符三项供给体系；所有玩家可以自用，专精玩家可参与市场。
- **宗门**：身份、门规、差事、贡献、共同研究和 NPC 关系；保留“世界宗门 + 玩家仙盟”的双层结构。
- **同道与集市**：好友、队伍、附近修士、聊天、寄售行和定时拍卖会；交易状态由服务端权威记录。
- **斗法**：按同意切磋、问剑台匹配、资源争夺、宗门战四层递进，严格划分安全区和竞争区。

完整的板块、循环、首发边界及导航草图见[游戏板块与功能架构草案](游戏板块与功能架构草案.md)。

## 5. 美术与动画方案

### 推荐视觉方向：新国风工笔水墨

- 世界：水墨留白、远景雾化、山水层叠；主色青黛、雾白、岩墨。
- 人物：工笔线条、清晰剪影、少量丝绸/金属材质；朱砂、鎏金仅用于稀有度、危险提示和关键角色。
- 战斗：轮廓清楚优先于写实；技能特效要有“符箓、阵纹、墨痕、灵光”的识别语言。
- 参考原则：观察《一念逍遥》的留白和色彩克制、观察同类作品的洞府/地图可读性；不复制任何角色、构图、图标、文案或资产。

### ComfyUI 是否需要

**不需要作为开工前置条件，但建议在美术量产阶段使用。** GPT Image 适合快速探索角色概念；ComfyUI 的优势是把已认可的角色风格、姿态、服装、线稿和局部区域稳定地批量控制，特别适合生成同一角色的敌我姿态、装备变体和特效草图。

它不会自动解决“游戏动画”问题：2D 动作仍要由分层素材、Spine 2D/序列帧、粒子特效与程序播放共同完成。技能中的人物动作、剑气和阵纹应拆开播放，才能复用、调速、打断和适配 PVP。

### 资产管线

1. 世界观与角色设定卡（身份、性格、元素、轮廓、配色禁区）。
2. 使用 GPT Image 生成多方案概念图、正侧背设定图和立绘草案；用 ComfyUI（可选）进行姿态控制、局部重绘与批量变体；由美术定稿并保留来源、版本和授权记录。
3. 由美术拆分为游戏可用的身体层、服饰层、武器层与特效层，输出统一规格的战斗角色。
4. Codex 根据动作表编写豆包提示词；豆包生成动势参考或连续帧素材。
5. 动画人员将素材清理、统一透视与比例、制作序列帧或 Spine 2D 骨骼动画；在设备上验收帧率、可读性与包体。

**关键限制：** AI 图像/视频不能直接替代可运行资产。角色一致性、透明背景、可控帧数、循环衔接、授权与风格统一，都必须由人工整理和验收。

## 6. 技术与上线建议

| 方案 | 适配度 | 判断 |
|---|---|---|
| **Cocos Creator + TypeScript** | 很高 | 推荐。引擎运行时开源且采用 MIT 许可证，工具可免费下载；轻量 2D、微信小游戏构建路径直接，并可保留原生移动端能力。具体版本及插件/服务条款须在立项时复核。 |
| Unity + C# | 中 | 若未来明确要高规格 3D、复杂特效或多平台深度商业化，可重新评估；首发微信小游戏会增加适配与性能管理压力。 |
| 虚幻引擎 | 低 | 强项为高保真 3D，不符合当前 2D 与微信优先目标。 |
| Godot | 中 | 引擎采用 MIT 许可证、无版税，适合原型和 App；但中国微信小游戏的成熟生产、国内 SDK 与服务接入仍不作为首发首选。 |

推荐发行顺序：

1. Cocos Creator 制作内部原型；
2. 微信小游戏小范围测试，验证“战斗是否爽、修炼是否有目标、7 日留存是否可接受”；
3. 根据数据扩充内容与服务器；
4. 当内容量和留存成立后，再发布 Android/iOS App，并保留同账号数据。

需要在开发前决定的服务能力：账号登录、存档、随机种子、配置热更新、公告邮件、排行榜、拍卖结算、PVP 房间与战斗结算、支付、埋点、反作弊、客服后台和故障监控。物品、货币、掉落与胜负以服务端为准；可先用托管后端验证，正式上线前再按并发和成本选择服务器方案。

## 7. Codex 项目与任务分组

确认立项后，在《寻岚记》项目下建立一个主项目任务，并建立以下独立 Codex 子任务；每个子任务都有自己的需求、验收项和周报，但由“项目总控”维护同一份版本目标。

| 分组 | 负责内容 | 首个交付物 |
|---|---|---|
| 0. 项目总控 | 版本目标、风险、排期、任务板、决策记录 | 游戏立项书与 MVP 范围 |
| 1. 世界观与叙事 | 主线、地图、NPC、势力、任务文本 | 世界观圣经 v0.1 |
| 2. 系统与数值 | 战斗、修炼、随机机缘、装备、经济、拍卖、PVP、付费边界 | 核心循环、随机规则和数值表 |
| 3. 美术与动画 | 风格板、角色设定、场景、UI、特效、动作表 | 一名主角 + 一只敌人资产包 |
| 4. 客户端 | Cocos 工程、战斗、UI、地图、性能与资源管理 | 10 分钟可玩垂直切片 |
| 5. 服务端与在线 | 账号、存档、随机种子、组队、拍卖、PVP、排行榜、运营工具、安全 | 测试环境与权威结算接口 |
| 6. 测试、发行与运营 | QA、设备测试、埋点、商店素材、社区、合规清单 | 测试计划与上线清单 |

Codex 的职责是：维护任务文档、生成和审查代码、生成资产提示词、建立自动化测试与版本说明；世界观取舍、美术定稿、最终数值与上线审批仍需要由项目负责人确认。

## 8. MVP（第一个可玩版本）

不要一开始做完整网游。MVP 只需证明核心乐趣：

- 一名可选男女外观的初始角色；
- 雾隐原一张可探索地图、一处三层秘境；
- 三种普通敌人、一名首领；
- 御器/炼体/灵契各一个基础技能与一套升级选择；
- 采集、炼丹或炼器中选择一种制作玩法；
- 一条 10–15 分钟的新手引导主线，仅解释修炼与“岚”的环境现象；
- 一次个人机缘、一个区域随机词缀、一次定向重铸；
- 联网原型：服务端存档、拍卖行模拟和 1v1 对战原型。完整安全、支付与规模化运营不纳入垂直切片。

验收标准：中端手机稳定运行；新玩家不看说明也能完成首次战斗、首次修炼与首次奖励领取；开发团队能在一周内替换一名角色、一个敌人和一处关卡资源。

## 9. 目前缺少、但必须补齐的事项

- 目标玩家、年龄层、付费模型与单局/单日游玩时长；
- 战斗形态（横版、俯视角、回合制或半即时）与操作方式；
- 联网强度、同屏人数、PVP 的实时性、战力压缩与赛季规则；
- 角色性别、捏脸、职业固定或自由构筑的范围；
- 音乐、音效、配音和无障碍设计；
- 服务器预算、隐私/未成年人保护/内容审核/平台资质与版号等上线合规工作；
- 版本控制、资产命名、备份、版权来源台账、外包验收标准；
- 数据指标、灰度测试、客服和长期活动节奏。

## 10. 建议下一轮先确认的四项

1. 首发是否确定“微信小游戏优先、App 随后”，并采用 Cocos Creator？
2. 战斗选哪一种：俯视角即时 ARPG（推荐）、横版动作，还是回合制？
3. PVP 首发是否确认只做 1v1 论剑场，宗门战延后？
4. 美术是否确认“新国风工笔水墨”，并在量产阶段引入 ComfyUI？
